1. Executive summary

We propose an AI Reporting Assistant: a secure web portal where authorized users ask for inventory and financial reports in plain language and get back the report, its statistics and its charts within seconds.

The solution builds on an existing large language model (LLM) rather than training a new one. The LLM interprets each request, queries the client's own data in read-only mode, and writes the narrative. Every figure comes directly from the client's systems, never from the model.

Delivery takes 17 to 23 weeks in four phases: discovery, an inventory pilot, financial reporting, then wider rollout. Each phase ends with a client sign-off gate with a measurable target. A 4-week hypercare period follows go-live, then an optional support plan.

2. Background and problem statement

The client wants people using its systems to get inventory and financial reports on demand, tailored to what each person needs, complete with graphs and statistics.

Today, a custom report typically means a request to an analyst or IT team, a wait, and a fixed format. Users who need a different cut of the data, period or comparison must start over. An AI assistant removes that bottleneck while keeping the numbers accurate and access controlled.

3. Objectives and scope

The project lets authorized users self-serve accurate inventory and financial reports, cutting report turnaround from days to minutes.

Objectives

  1. Answer report requests written in plain English.
  2. Return a complete report: narrative summary, key statistics and charts.
  3. Export reports to PDF, Word and Excel.
  4. Guarantee every figure traces back to the source data.
  5. Restrict each user to the data their role permits.

In scope (indicative report types, to be confirmed in discovery)

  • Inventory reporting: stock levels, movements, ageing, slow-moving and fast-moving items, reorder alerts, warehouse comparisons
  • Financial reporting: revenue, expenses, profit and loss summaries, budget versus actual, period comparisons, across currencies, entities and the client's fiscal calendar
  • Web chat portal, report export, role-based access and audit logging
  • Hypercare for 4 weeks after go-live, handover documentation and admin training

Out of scope (initial release)

  • Writing to or changing source data (the system is read-only)
  • Forecasting and predictive analytics (candidate for a later phase)
  • Training a new language model from scratch
  • Calculating consolidation eliminations that the ERP does not already hold (reports use the ERP's consolidated figures)
  • Mobile apps (the portal will be mobile-friendly in the browser)

7. Proposed solution architecture

A request passes access control, the LLM plans a read-only query against a reporting copy of the data, results are analyzed and charted, and the finished report returns to the user.

The reporting data store is new in v1.1. It is a copy of the ERP data refreshed on a schedule (by default hourly for inventory, daily for finance), so reporting never slows down the live ERP. If the client already has a data warehouse, it fills this role and nothing new is built. Every report shows the time of the last refresh.

8. Delivery approach and phases

We recommend four phases over roughly 17 to 23 weeks, starting with an inventory pilot because it carries lower risk than financial data, followed by 4 weeks of hypercare.

Gate 3 is stricter than Gate 2 because wrong financial figures carry the highest risk. Finance supplies the test questions and expected answers from reports it already trusts. Durations are indicative and will be confirmed after discovery; the client approves each gate before the next phase starts.

12. Assumptions, dependencies and open questions

Assumptions and dependencies

  • The client provides read-only access to its inventory and finance data sources.
  • A client contact from IT, finance and operations is available for discovery and pilot testing.
  • Reports cover structured data held in databases or an ERP, not scanned documents.
  • Exchange rates and consolidated figures already exist in the ERP; the assistant reads them and does not calculate them.
  • Finance provides at least 100 test questions with known correct answers, taken from existing reports, before Phase 2 testing starts.
